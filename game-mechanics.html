SEEKING THE DEEP

Пошаговый подводный rogue-lite — механика и архитектура

Концепция игры

Seeking the Deep — подводный rogue-lite с пошаговой механикой. Игрок управляет дайвером, спускающимся в океанские глубины. Каждый уровень процедурно генерируется, враги действуют только в ответ на ход игрока. Смерть перманентна для текущего забега, но жемчуг сохраняется для мета-прогрессии.

Игровой цикл (один ход)

Игрок действует (WASD/стрелки/Space) → O₂ −1 → Подбор предметов на новой клетке → Сбор воздуха из «воздушного кармана» → Пересчёт видимости (BFS от игрока, радиус = light) → Ход всех врагов (Chase / Patrol) → Проверка смерти / выхода / удушья

Генерация карты: клеточный автомат

Алгоритм создаёт естественные пещерные структуры. Стартовое заполнение ~44% стен, затем 4 итерации клеточного автомата по правилу:

Если у клетки (с учётом 8 соседей) ≥5 стен ИЛИ 0 стен → стена Иначе → пол

После этого отсекаются изолированные «острова» — все клетки пола, не входящие в крупнейшую связную область (≥80 тайлов), превращаются в стены. Вход размещается в верхней части карты, выход — в нижней. Между входом и выходом проверяется BFS-путь.

Если за 20 попыток не удалось сгенерировать проходимую карту, используется fallback — открытый прямоугольник со стенами по периметру.

Система видимости (Fog of War)

Видимость пересчитывается каждый ход с помощью BFS от позиции игрока. Радиус обзора складывается из базового (5) и бонусов: +1 за уровень в магазине и +2 от Светового камня. Стены блокируют распространение света; стены, смежные с видимым полом, тоже показываются.

Исследованные, но невидимые клетки отрисовываются тускло (40% альфа). Враги и предметы на них скрыты. Неисследованные клетки — полностью чёрные.

Пошаговая система и бой

Игра использует классическую пошаговую механику: мир обновляется только после действия игрока. Враги не имеют собственного таймера — каждый враг делает один ход после игрока.

Боевая система (bump-атака)

Атака происходит при движении на клетку врага. Нет отдельной команды «атаковать» — бой неотделим от перемещения. Игрок наносит урон при входе в клетку врага, враг атакует в ответ в свой ход.

Урон игрока = 5 (база) + уровень_атаки × 2 + 3 (если Гарпун) Максимум: 5 + 20 + 3 = 28

AI врагов

Каждый враг действует по одному из двух режимов:

  • Chase — игрок в радиусе зрения врага (Manhattan-дистанция). Враг движется к игроку, выбирая клетку, минимизирующую расстояние. Если смежен — атакует.
  • Patrol — игрок вне зоны видимости. Враг возвращается к точке спавна, выбирая случайное направление среди оптимальных.

Враги не проходят сквозь стены и других врагов.

Глубина и сложность

Игрок начинает на глубине 1 и спускается, находя выход (зелёный ▼) на каждом уровне. При спуске:

  • Глубина увеличивается на 1
  • Игрок восстанавливает +5 HP (до максимума)
  • Игрок получает +30 O₂ (до максимума)
  • Генерируется новый уровень с усиленными врагами

Состояние при смерти

При смерти (HP ≤ 0) забег завершается. Показывается статистика: макс. глубина, убийства, жемчуг за забег. Весь собранный жемчуг прибавляется к общему счёту и сохраняется в localStorage.

Архитектура кода

Игра реализована в одном HTML-файле (seeking-the-deep.html), без внешних зависимостей. Код (~990 строк) структурирован в логические блоки:

Карта модулей

Структура G (глобальное состояние)

G = { screen, // текущий экран (title/game/death/shop) depth, // текущая глубина map: number[][], // сетка 30×20 (T_WALL=0, T_FLOOR=1) player: { x, y, hp, maxHp, oxygen, maxOxygen, attack, light, inv[] }, enemies: [{ type, x, y, hp, atk, sx, sy, vision }], groundItems: [{ type, x, y }], airPockets: [{ x, y, used }], explored: bool[][], // 30×20 — какие клетки были увидены visible: bool[][], // 30×20 — какие клетки видны сейчас messages: [], // лог сообщений (до 40) run: { kills, depth, maxDepth, pearls }, // статистика забега meta // постоянные данные из localStorage }

Поток данных рендеринга

render() вызывается после каждого processTurn(): 1. Очистка canvas 2. Отрисовка тайлов пола (dim для explored, dark для visible) 3. Стены по смежным видимым клеткам 4. Выход (▼) 5. Воздушные карманы (синие круги) 6. Предметы (цветные точки) 7. Враги (цветные круги + буква + HP-бар) 8. Игрок (голубой круг + свечение)

Инициализация

window.onload: → defMeta() // загрузка localStorage или значения по умолчанию → resizeCanvas() // подгон размера тайла под экран → render() // стартовый экран (титул)

Полный цикл забега

startGame(): → playerBase() // создание игрока с учётом апгрейдов → applyStartItems() // выдача стартовых предметов → generateFloor() // карта + враги + предметы → updateVisibility() // первый расчёт обзора → render() // отрисовка На каждом ходу: → processTurn(dx, dy) → движение / bump-атака → O₂--, подбор, воздух → updateVisibility() → enemyTurns() (каждый враг: chase или patrol) → checkPlayerState() (смерть, выход, удушье) → render()
